# Agent Skill

Agent Skill — готовый пакет инструкций для AI-агентов (Claude Code, Cursor и других клиентов,
которые читают `SKILL.md`). Он учит агента работать с проектом по FEOD: решать, куда положить
код, добавлять модули и страницы, проверять импорты, подключать плагины ESLint/Oxlint и
разбирать их ошибки.

Скилл не генерирует правила автоматически и не заменяет линтер. Правила FEOD проверяют
[плагины ESLint и Oxlint](/linting/); скилл помогает агенту следовать тем же правилам до
того, как линтер найдёт нарушение.

## Установка

Скилл лежит в репозитории в каталоге [`skills/feod`](https://github.com/Sdju/feod/tree/main/skills/feod)
и ставится через [`skills`](https://github.com/vercel-labs/skills) — менеджер скиллов, который
сам кладёт файлы в каталоги нужных агентов (Claude Code, Cursor и других). Нужен Node.js.

```sh
# в корне проекта
npx skills add Sdju/feod

# для всех проектов (пользовательский каталог)
npx skills add Sdju/feod --global
```

Команда спросит, в какие агенты установить скилл. Чтобы обойтись без вопросов, укажите агента
и скилл явно: `npx skills add Sdju/feod --skill feod --agent claude-code --yes`. Флаг `--copy`
копирует файлы вместо символических ссылок.

Полезные команды:

```sh
npx skills add Sdju/feod --list   # показать, что есть в репозитории, ничего не устанавливая
npx skills list                   # установленные скиллы
npx skills update                 # обновить до последней версии
npx skills remove feod            # удалить
```

Установленный каталог самодостаточен: `SKILL.md`, `references/` и `scripts/feod.mjs`. Файлы
скилла под проект не правят — проектные настройки хранятся в [профиле](#профиль-проекта).
Скилл можно подключить и вручную: скопируйте `skills/feod` в каталог скиллов агента
(например, `.claude/skills/feod` или `.cursor/skills/feod`).

## Что делает агент

1. **Читает профиль проекта.** Если в корне есть `feod.profile.md`, он важнее любых
   умолчаний скилла. Если профиля нет, а задача зависит от варианта (имена слоёв,
   политика `pages`/`common`), агент запускает init. В остальных случаях работает по
   базовой модификации.
2. **Смотрит на проект так же, как FEOD.** Команда `node scripts/feod.mjs info --json`
   показывает источник конфигурации, корни, слои, модули и их публичные входы, а также
   расхождения между конфигом, диском и профилем. Нужен Node.js 20.19 или новее, установка
   не требуется. Команда не проверяет импорты: этим занимаются линтеры.
3. **Выбирает инструкцию под задачу:**

   | Задача | Файл |
   | --- | --- |
   | Куда положить сущность, реорганизация, миграция | `references/structure.md` |
   | Новый модуль или страница, чек-лист завершения, новый проект | `references/workflows.md` |
   | Допустимость импорта, модификации, антипаттерны | `references/rules.md` |
   | Установка плагинов, ошибки линтера | `references/lint.md` |
   | Зафиксировать вариант проекта | `references/init.md` |
   | Примеры кода для фреймворка | `references/templates/` |

4. **Проверяет результат** перед завершением: импорты соответствуют матрице слоёв и
   профилю, модули экспортируют только через `index.ts`, страницы и `app` без бизнес-логики,
   а проверки линтера проходят, если он подключён.

## Профиль проекта

`feod.profile.md` фиксирует выбор проекта: модификацию (`base`, `commonless`,
`common-module`), `multiapp`, политику страниц, имена слоёв, `common.allowIndex`,
транзитные модули и другие параметры, которые схема `feod.config.json` не выражает.
Профиль — единственный проектный файл скилла, его стоит коммитить в репозиторий.

Init-сценарий:

1. **Определяет** фреймворк, линтер, `srcRoot`, алиас и имена слоёв по `package.json`,
   конфигам и структуре каталогов.
2. **Спрашивает** только то, что определить нельзя (не более трёх вопросов): модификацию,
   политику страниц и подключение линтера.
3. **Показывает карточку** профиля и ждёт подтверждения.
4. **Записывает** `feod.profile.md` и, если выбрано, конфигурацию линтера. Поля, которые
   поддерживает схема, попадают в единственный источник: `package.json#feod` или
   `feod.config.json`; остальные остаются только в профиле.

Чтобы изменить профиль, запустите init снова: профиль и конфигурация перезаписываются вместе.

## Ограничения

- Скилл — инструкции для агента, а не гарантия. Нарушения архитектуры ловит линтер;
  подключите его: [ESLint и Oxlint](/linting/).
- Качество зависит от модели агента. Скилл пока проверялся на небольшом числе проектов —
  если нашли неточность, [сообщите об этом в репозитории](https://github.com/Sdju/feod/issues).
- Справочники примеров кода сейчас есть только для Vue SPA.
- Исходники скилла — `skill/` и `packages/skill-cli`; `skills/feod` собирается командой
  `pnpm run skill:pack` и правится только через исходники.
